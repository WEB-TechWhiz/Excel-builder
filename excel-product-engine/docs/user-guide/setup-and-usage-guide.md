# Excel Product Engine — Setup & Usage Guide

This guide covers three things:
1. Setting the project up on your machine
2. Generating an Excel file with what's built so far (Phases 1–4)
3. Starting a brand-new product on top of the engine

> **Status check:** Phases 1–4 (foundation, core engine, design system,
> components) are implemented and tested. `build.py` / `validate.py` /
> Financial OS itself are **not built yet** (Phases 5–9) — every example
> below only uses what's actually working today.

---

## 1. Project Setup

**Requires:** Python 3.12+

```bash
# 1. Unzip and open the project
unzip excel-product-engine.zip
cd excel-product-engine

# 2. Create and activate a virtual environment
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Install the engine + dev tools (editable install)
pip install -e ".[dev]"

# 4. Verify everything works
pytest                            # should show "92 passed"
ruff check src tests              # should show "All checks passed!"
mypy src/excel_engine             # should show "Success: no issues found"
```

If all three commands pass, the setup is good.

## 2. Generating an Excel File

Everything runs through three pieces:

| Piece | What it does |
|---|---|
| `ExcelWorkbook` | Create/save the workbook, add sheets |
| `StyleManager` | Theme-aware fonts, fills, borders (`"premium"`, `"minimal"`, `"classic"`) |
| `excel_engine.components` | Ready-made pieces: title banners, KPI cards, tables, navbars, buttons, progress bars, footers |

Every component takes `(worksheet, style, ..., top_left="A1")` and
**returns the `CellRange` it occupied** — use that to position the next
element instead of guessing row numbers.

### Full working example

Save this as `build_sales_tracker.py` in the project root and run
`python build_sales_tracker.py`:

```python
from excel_engine.config.product_config import ProductConfig
from excel_engine.core.workbook import ExcelWorkbook
from excel_engine.core.metadata import WorkbookMetadata
from excel_engine.styles.style_manager import StyleManager
from excel_engine.components import (
    add_title_banner,
    add_kpi_card,
    add_navbar,
    add_data_table,
    add_footer,
)

# 1. Describe the product
config = ProductConfig(
    name="Sales Tracker",
    version="1.0.0",
    author="MuffinCodes",
    theme={"name": "premium"},   # or "minimal" / "classic"
)

# 2. Resolve the theme into ready-to-use styles
style = StyleManager.for_theme(config.theme.name)

# 3. Create the workbook
workbook = ExcelWorkbook(
    metadata=WorkbookMetadata(title=config.name, author=config.author, version=config.version)
)

# 4. Build the Dashboard sheet
dashboard = workbook.add_sheet("Dashboard")
add_navbar(dashboard, style, ["Dashboard", "Orders"], top_left="A1",
           active="Dashboard", item_width=3)
add_title_banner(dashboard, style, config.name, subtitle="Auto-calculated",
                  top_left="A2", width=9)
add_kpi_card(dashboard, style, "Total Revenue", "=SUM(Orders!C2:C51)",
             top_left="A5", number_format='"₹"#,##0')
add_kpi_card(dashboard, style, "Total Orders", "=COUNTA(Orders!A2:A51)",
             top_left="E5", number_format="#,##0")
add_footer(dashboard, style, f"Generated by {config.name} v{config.version}",
           top_left="A9", width=9)

# 5. Build the Orders data sheet
orders = workbook.add_sheet("Orders")
add_data_table(orders, style, ["Date", "Customer", "Amount"],
                n_rows=50, table_name="Orders")

# 6. Save
path = workbook.save("output/sales_tracker.xlsx")
print("Saved:", path)
```

Run it:

```bash
python build_sales_tracker.py
```

Open `output/sales_tracker.xlsx` — you'll have a Dashboard with a navbar,
title banner, two live KPI cards, a footer, and an Orders sheet with a
real banded Excel Table. Type numbers into the Orders table and the KPI
cards on the Dashboard update automatically (they're real `SUM`/`COUNTA`
formulas, not static text).

### The other components

```python
from excel_engine.components import add_button, add_labeled_input, add_progress_bar, add_section_header

add_button(dashboard, style, "Back to Dashboard", top_left="H2", target_sheet="Dashboard")
add_labeled_input(settings, style, "Currency", top_left="A1", default_value="INR")
add_progress_bar(goals, style, "B2:B10")   # cells hold 0..1 fractions
add_section_header(dashboard, style, "Chart Source Data", top_left="T5")
```

## 3. Starting a New Product

A "product" is just: a `ProductConfig` + sheet-building code that calls
into `excel_engine.components`. There's no scaffolding command yet
(that's Phase 9's `build.py`), so for now you do it by hand — which is
exactly what the example above already showed. To make it a proper,
reusable product rather than a one-off script:

1. **Create a folder under `products/`**

   ```bash
   mkdir -p products/sales_tracker/sheets
   ```

2. **Add a config file** — `products/sales_tracker/config.yaml`:

   ```yaml
   product:
     name: Sales Tracker
     version: 1.0.0
     author: MuffinCodes
   locale:
     currency: INR
     language: en
     date_format: DD/MM/YYYY
   theme:
     name: premium
   ```

3. **Load it instead of hard-coding the config**:

   ```python
   from excel_engine.config.product_config import ProductConfig

   config = ProductConfig.from_yaml("products/sales_tracker/config.yaml")
   ```

4. **Split sheet-building into functions**, one per sheet, e.g.
   `products/sales_tracker/sheets/dashboard.py`:

   ```python
   from excel_engine.core.workbook import ExcelWorkbook
   from excel_engine.styles.style_manager import StyleManager

   def build_dashboard(workbook: ExcelWorkbook, style: StyleManager, product_name: str) -> None:
       dashboard = workbook.add_sheet("Dashboard")
       # ... add_navbar / add_title_banner / add_kpi_card calls here
   ```

5. **Add a `product.py`** that ties it together (config → workbook →
   call each sheet builder → save) — this becomes the file Phase 9's
   `build.py financial_os`-style command will eventually call for any
   product name, once it exists.

6. **Write it a test** under `tests/product/`, following the same
   pattern as `tests/integration/test_dashboard_components_integration.py`
   — build the product, save it, reload with `openpyxl.load_workbook`,
   assert the key cells/tables/formulas are correct.

This keeps every future product (Business Dashboard, CRM, whatever's
next) shaped the same way, so Phase 9's automation has a consistent
thing to build against.

## 4. Generating a Workbook from a Plain-English Prompt (LLM bridge)

Instead of writing the Python yourself (section 2), you can describe
the workbook in plain English and let Claude turn it into a validated
plan that the same deterministic builder then executes.

```bash
# one-time setup
pip install -e ".[llm]"
cp .env.example .env
# edit .env and set: ANTHROPIC_API_KEY=sk-ant-...

# generate
python -m excel_engine.llm.generate "Make me a sales tracker with total revenue, average order value, and total orders, tracking Date, Customer, and Amount"
```

Or from Python:

```python
from excel_engine.llm import generate_workbook

path = generate_workbook("Make me a sales tracker with total revenue and total orders")
print(path)  # output/sales_tracker.xlsx
```

**What actually happens under the hood:**

1. Your prompt goes to Claude with a forced tool call — Claude can
   *only* reply by filling in a fixed schema (`WorkbookSpec`): product
   name, theme, one or more data tables (name + columns), and a
   dashboard with KPI cards (label, which table/column to aggregate,
   which aggregate function, number format).
2. That plan is validated — unknown theme, duplicate sheet names, or a
   KPI pointing at a column that doesn't exist all get rejected before
   anything is built.
3. The validated plan is hand ed to the exact same
   `excel_engine.components` used everywhere else in this guide — the
   LLM never writes code or touches a cell directly.

This means the worst a bad/ambiguous prompt can do is fail validation
with a clear error — it can't corrupt the workbook or produce broken
formulas.

**Current limits** (matches what Phases 1–4 can build so far): only
dashboard + KPI cards + data tables — no charts, no multi-table
formulas yet. Those arrive as their own phases (6–8) and the LLM schema
will grow to match.

## 5. Formulas & Typed Tables (Phase 5)

For safe formulas, use `Formula` instead of writing Excel syntax by hand:

```python
from excel_engine.formulas import Formula

Formula.sum("Orders", "Amount")                                   # =SUM(Orders[Amount])
Formula.sumifs("Orders", "Amount", ("Colorway", "Saddle Amber"))
Formula.average("Orders", "Amount")
Formula.index_match("Income", "Amount", '"Salary"', "Income", "Source")
```

These build **structured table references**, so `"Orders"` must be a
real Excel Table — which is exactly what `add_typed_table` creates:

```python
from excel_engine.data.tables import ColumnSchema, add_typed_table

add_typed_table(
    orders_sheet, style,
    columns=[
        ColumnSchema(header="Date", type="date"),
        ColumnSchema(header="Colorway", type="list", options=("Amber", "Teal")),
        ColumnSchema(header="Amount", type="currency"),
    ],
    n_rows=50, table_name="Orders",
)
```

Number formats and dropdown validation for the `"list"` column are
applied automatically. For realistic example rows (not "Test 1/Test
2"):

```python
from excel_engine.data.demo_data import write_demo_rows

write_demo_rows(
    orders_sheet, style, headers=["Date", "Colorway", "Amount"],
    rows=[{"Date": "2026-07-04", "Colorway": "Amber", "Amount": 2499}],
    top_left="A2",
)
```

## 6. Charts, Navigation & Protection (Phase 6)

```python
from excel_engine.charts import add_bar_chart, add_line_chart
from excel_engine.navigation import apply_menu_to_all_sheets, validate_all_hyperlinks
from excel_engine.protection import apply_standard_protection

# Charts read from a small, formula-driven helper table — stays correct
# as data changes, no "regenerate the chart" step.
add_bar_chart(
    dashboard, style, "Revenue by Colorway", "Orders", "Colorway", "Amount",
    categories=["Amber", "Teal", "Plum"], anchor_cell="B9", data_top_left="T5",
)
add_line_chart(
    dashboard, style, "Revenue Trend", "Orders", "Date", "Amount",
    anchor_cell="K9", data_top_left="T15", periods=6,
)

# One call, consistent navbar (correct page marked active) on every sheet.
apply_menu_to_all_sheets(workbook, style, ["Dashboard", "Orders", "Goals"])
assert validate_all_hyperlinks(workbook) == []   # catches links to missing sheets

# Lock everything except the given ranges, then protect the sheet
# (formatting/sorting/AutoFilter stay allowed).
apply_standard_protection(orders_sheet, editable_ranges=["A2:C51"])
```

`add_pie_chart` / `add_doughnut_chart` share `add_bar_chart`'s
signature. `categories` must be listed explicitly — no `UNIQUE()` (see
docs/architecture.md for why).

## 7. Validating a Workbook (Phase 7)

Run this before handing a generated file to anyone:

```python
from excel_engine.validation import validate_workbook

report = validate_workbook(
    workbook, product_name="Sales Dashboard",
    required_sheets=["Dashboard", "Orders"],
    required_tables={"Orders": ["Orders"]},
    expected_formula_cells=[("Dashboard", "A6")],
    expected_locked_formula_cells=[("Dashboard", "A6")],
    expected_unlocked_input_ranges=[("Orders", "A2:C21")],
)
print(report.format())
assert report.passed
```

Catches: missing sheets/tables/named ranges, a formula referencing a
table/column/sheet that doesn't exist, duplicate table names, dangling
hyperlinks, and formula/input cells with the wrong lock state — all in
one call, categorized so you can see exactly which check failed.

## 8. Financial OS — the first full product (Phase 8)

Everything above, assembled into a real 9-sheet product:

```bash
python -c "from products.financial_os.product import build_financial_os; \
build_financial_os().save('output/financial_os.xlsx')"
```

Dashboard, Income, Expenses, Bills, Investments, Net Worth, Goals,
Reports, Settings — realistic demo data, 7 live KPI cards, 4 charts,
computed columns, protected input ranges, and a navigation menu on
every page. To see how a full product is structured, read (in order):

1. `products/financial_os/config.py` — the `ProductConfig`
2. `products/financial_os/data/demo_data.py` — realistic rows per sheet
3. `products/financial_os/formulas/financial_metrics.py` — what "Net
   Worth"/"Savings Rate" mean (business logic, kept out of the engine)
4. `products/financial_os/sheets/*.py` — one file per sheet
5. `products/financial_os/product.py` — the orchestrator

This is the reference pattern for building a second product — copy the
shape, not the content.

## 9. Command-Line Pipeline (Phase 9)

Now that a product is registered (`products/registry.py`), you don't
need the Python snippet above — use the CLI:

```bash
# build: config -> workbook -> validate -> export
# (refuses to export if validation fails)
python scripts/build.py financial_os

# validate an already-built file
python scripts/validate.py output/Financial_OS_v1.0.0.xlsx

# build + validate + package for release
python scripts/release.py financial_os
python scripts/release.py financial_os --force   # overwrite an existing release
```

`release.py` produces:

```
dist/financial-os/
├── Financial_OS_v1.0.0.xlsx
├── Documentation/README.md
├── License/LICENSE.txt
└── Release/RELEASE_NOTES.txt
```

To add a second product to all three commands, add one entry to
`products/registry.py` — nothing else changes.

## 10. Project Structure Reference

```
excel-product-engine/
├── src/excel_engine/
│   ├── core/          # ExcelWorkbook, Worksheet, CellAddress, CellRange
│   ├── config/         # ProductConfig, EngineSettings, theme registry
│   ├── styles/          # StyleManager, colors, fonts, borders, fills, alignment
│   ├── components/       # add_kpi_card, add_data_table, add_navbar, etc.
│   └── exceptions/        # typed exception hierarchy
├── products/<name>/     # your products live here (see section 3)
├── tests/
│   ├── unit/            # one file per engine module
│   ├── integration/      # components working together, real save/reload
│   └── product/           # full-product builds (once products exist)
└── output/              # generated .xlsx files land here
```

Full architecture rationale (why each split exists) is in
`docs/architecture.md`. Phase-by-phase build history is in
`CHANGELOG.md`. Current roadmap status is in `README.md`.
